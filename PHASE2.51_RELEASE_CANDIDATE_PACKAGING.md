# Phase 2.51 — Release Candidate Packaging

This archive is a release-candidate packaging pass after historical capability reconciliation.

## Changes
- Added `scripts/check-release-lock-consistency.mjs`.
- Added `bun run check:release-lock` to the release scripts.
- `bun run verify:release` now checks the root `esbuild` lock resolution before lint/build/test.
- CI runs the same lock-consistency check before `bun install --frozen-lockfile`.
- The project directory/archive identity is normalized to `Project-Jerry-v46`.

## Deliberate blocker
The current archive still contains the pre-regeneration `bun.lock`: its root `esbuild` resolution is `0.25.12`, while `package.json` requires `^0.28.2`.

This archive therefore **must not be called release-ready**. The lockfile must be regenerated by Bun in a network-enabled environment. The new guard intentionally fails until that happens.

## Required release execution
```bash
bun add -d esbuild@^0.28.2
bun install
bun run check:release-lock
bun install --frozen-lockfile
bun run db:test:push
bun run test:tenant
bun run verify:release
```
